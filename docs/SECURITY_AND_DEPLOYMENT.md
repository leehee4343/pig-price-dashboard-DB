# 보안 및 배포 원칙

## 현재 대시보드의 역할

`index.html`은 인증 서버가 없는 정적 관리자 분석 화면이다. 브라우저에 전달된 데이터는
사용자가 개발자 도구로 모두 열람할 수 있으므로 이 파일만으로 업체별 접근 권한을 안전하게
구현할 수 없다.

업체가 자기 자료만 조회하는 포털은 다음 구성으로 별도 구현해야 한다.

1. 서버 측 로그인과 세션 관리
2. 사용자 계정과 업체 고유번호의 서버 측 연결
3. 모든 조회 API에서 로그인 업체 조건을 강제로 적용
4. 관리자 역할과 업체 역할의 권한 분리
5. 감사 로그 및 세션 만료

화면에서 업체 선택 상자를 숨기거나 비밀번호를 JavaScript에 넣는 방식은 접근 통제가 아니다.

## 데이터 배포

- 공개 정적 저장소에 원본 Excel을 배포하지 않는다.
- HTML에는 집계에 필요한 공개 필드만 넣는다.
- 업체정보에서는 `업체명`, `시도명`, `사용여부`만 내장한다.
- 연락처, 담당자, 사업자번호, 업체 API 키는 HTML과 브라우저 저장소에 넣지 않는다.
- 사용자가 선택한 Excel은 현재 브라우저 메모리에서만 분석한다.

현재 Git 이력에 이미 포함된 토큰과 업체 API 키는 파일에서 삭제하는 것만으로 폐기되지 않는다.
운영자는 기존 GitHub 토큰과 업체 API 키를 교체하고, 필요하면 저장소 이력도 정리해야 한다.

## 데이터 갱신

관리자 PC에서 원본 Excel을 준비한 뒤 다음 명령으로 공개용 HTML을 생성한다.

```powershell
npm run update
```

생성 결과를 검토한 후 일반적인 Git 검토·승인 절차로 배포한다. 브라우저에 GitHub 토큰을
내장하여 저장소에 직접 쓰는 기능은 사용하지 않는다.
